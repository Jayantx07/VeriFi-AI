CASE 07/10 · EVIDENCE
CHAIN OF CUSTODY · DATA, EVIDENCE, VALIDATION PLAN & KEY ASSUMPTIONS

Synthetic data in, verifiable evidence out.

A · DATA
  • Prototype: synthetic only. A fictional company (Kestrel Infra) with people, vendors, emails, meetings and payments.
  • Public: news reports of the Arup case. No bank, customer or platform data.
  • Production: customer-authorised finance mailboxes, meeting metadata and ERP data under a DPA.
B · EVIDENCE
  • Every decision, passkey signature and analyst action is a hash-chained, append-only record.
  • Chain heads signed with AWS KMS, stored under S3 Object Lock; an independent verifier re-checks it all.
  • Output: 1930 / cybercrime.gov.in incident pack + bank recall draft.
C · VALIDATION PLAN
  • 14 red-team regressions: forged or replayed passkeys, cross-payment release, prompt injection, fail-open, tenant leaks.
  • 7 end-to-end scenarios asserting exact scores (S1 87.5 · S2 59.0 · S3 6.0 · S4 25.0).
  • LLM eval: ≥ 90% field accuracy on 40 emails · decision p95 ≤ 300 ms · 60-day pilot shadow mode.
D · KEY ASSUMPTIONS
  • Payments pass a release step we can hook: an ERP API call or the bank-upload file.
  • Each authority enrolls a passkey on their own phone.
  • If the account never appears in an ingested channel, rule R1 still forces confirmation. Weights stay expert priors until pilot calibration.

CASE 08/10 · SAFEGUARDS
PROTOCOL · PRIVACY, SECURITY, SAFETY & MISUSE SAFEGUARDS

Private, secure, safe, and hard to misuse.

01 / PRIVACY

Privacy

  • Account numbers, IFSC and phones tokenized (HMAC) before any LLM or graph
  • Raw values only in an encrypted vault; analyst reads are logged
  • Aadhaar detected and dropped
  • Finance mailboxes only; India region; built for the DPDP Act 2023
02 / SECURITY

Security

  • FIDO2 passkeys for every human, no passwords
  • Challenge bound to transaction + decision; single-use
  • Signed ERP calls and webhooks; tenant isolation
  • Dependency down → high-value payments step up
03 / SAFETY

Safety

  • Never auto-rejects: people decide every hold
  • Every decision explained: rules fired + signal contributions
  • The LLM can add risk, never remove it
  • Requesters can’t confirm their own payment
04 / MISUSE

Misuse

  • Purpose-limited by contract: no HR or productivity monitoring
  • Rogue enrollment blocked: one-time admin link, user alerted, two admins to replace
  • Detailed signals go to confirmers, not requesters
  • VeriFi prepares reports; humans file them
DESIGN RULEVeriFi can delay a payment. It can never move money, reject a payment, or accuse a person. People make every final call.
